# src/components/coding

Feature components for the Coding Interview Trainer module.

## Files

| File | Description |
|------|-------------|
| `DifficultyBadge.tsx` | Small pill badge for exercise difficulty (easy/medium/hard). Reads colours from `DIFFICULTY_COLORS` in `@/config`. |
| `ExerciseCard.tsx` | Read-only summary card showing title, difficulty badge, and knowledge-pattern tags. Tags are resolved from a `knowledgeMap` prop to avoid extra data fetches. |
| `KnowledgeCard.tsx` | Expandable accordion card showing a knowledge item's name, category chip, and full markdown explanation (rendered via `react-markdown`). Client component. |
| `CodingSessionConfig.tsx` | Session configuration form — difficulty filter, exercise count. On "Start Session" → `POST /api/coding/session` → stores `CodingTestSession` in `sessionStorage` → navigates to `/coding/test`. Also exports the `CODING_SESSION_KEY` constant. |
| `PatternPicker.tsx` | Row of pattern buttons (Sliding Window, DFS, BFS, DP, …) from `@/config/decisionTree`. User picks the pattern they believe applies; the picked button turns green/red once an answer is locked in. |
| `DecisionTreeView.tsx` | Renders an exercise's correct pattern as: (1) a correct/incorrect banner against the user's pick, (2) a compact visual tree diagram — square nodes alternating orange "question" boxes (only the question actually asked, starting at root) and answer rows (from `getDecisionPath` + `getChildren`, taken square green, untaken siblings grey, only ever expanding the taken node's own children on the next step), arrows connecting each question↔answer step; each row's nodes flex to fill the full diagram width evenly (capped per node to avoid a lone item stretching too wide) and wrap their own text vertically rather than overflowing or scrolling, (3) the same path as detailed text at normal reading size (question + justification per node, exercise override via `patternJustifications`), (4) a "Ruled Out Here" section (from `getRuledOutAlternatives`) with full justification text for the sibling patterns at the final branching node. Does *not* own the "Show Full Decision Tree" trigger — that lives in `test/page.tsx` so it's reachable before a pattern is picked too. |
| `FullDecisionTreeModal.tsx` | Modal (via `ui/Modal`) rendering the *entire* template tree (not just one exercise's path) with `react-d3-tree` — a zoomable/draggable, auto-laid-out SVG graph. Data comes from `buildFullDecisionTree()` (`@/config/decisionTree`), which mirrors `DecisionTreeView`'s layout by inserting a synthetic "question" node between every branching node and its children. Custom square node rendering via `renderCustomNodeElement` + `foreignObject` reuses the same orange/green/grey palette. `pathNodeIds`/`leafNodeId` are optional — omit both for a blank tree (all questions orange, all answers white bg/black text, nothing ruled out yet); pass them once a pattern is picked to highlight that exercise's path the same way the inline diagram does. Pan via click-and-drag (native trackpad two-finger-scroll-to-pan isn't supported — `react-d3-tree`'s underlying `d3-zoom` treats all wheel events, including trackpad scroll, as zoom; only `ctrlKey`-wheel magnitude differs for pinch). |
